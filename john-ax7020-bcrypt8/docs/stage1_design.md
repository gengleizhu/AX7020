# 阶段1设计与验收

本阶段的目标是为后续双PYNQ-Z2系统提供可信的单Core算法和原始协议基线。
器件固定为xc7z020clg400-1，仿真时钟100MHz。设计代码为原John RTL，
测试驱动与软件参考由本工程提供；结果必须由实际RTL运算产生。

## 测试组织

1. 软件参考使用CPU BF_common.c的1024个S常量，与S_data.txt逐项核对，
   再执行独立的EksBlowfish算法。9个标准字符串的23字节结果必须一致，才生成完整24字节向量。
2. tb_expand验证18个Expanded Key字及反压，覆盖x版本符号扩展与常规版本。
3. tb_core直接驱动1054字初始化和31字任务输入，读回PN/四组S/PD以核对装载，
   以微码IP=25的进入次数核对Cost循环，再验证257bit帧和两个32位任务ID。
4. tb_invalid对错误进行独立实例测试，因为原模块不提供运行时复位。
5. tb_packet按原C任务创建顺序送配置、生成器和字典，经过原解析/算法/结果封包链路；
   FIFO输出只有16个字深度，周期性暂停读取以强制反压，实际D3输出落盘再由Python校验。
6. 单Core综合采用原始六文件，保留层次并检查fsm/unit/P/S及无Blackbox；100MHz是阶段1门槛。

## 实际工作文件

仿真顶层在sim/tb；生成数据在sim/vectors。每个自检设置独立超时并以$fatal表示失败。
Vivado脚本还检查日志中的STAGE1_PASS，防止仿真失败却被工具进程以0退出码掩盖。
报告生成器再次检查各测试日志和源码哈希。波形保留在build/project下XSIM运行目录，
关键最终数据复制至reports/stage1。

## 频率与资源

100/125/150MHz各自重新综合，允许工具因时序目标改变S盒存储映射，因此不能把某档资源简单视为固定值。
只对100MHz施加通过门槛，另外两档记录真实WNS。没有使用放宽false_path或修改算法来制造时序通过。
OOC报告中缺少输入/输出延时是工程边界限制，不代表端到端时序通过。
